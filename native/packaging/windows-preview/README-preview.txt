מסדר סינגלים: תצוגה מקדימה עם שני המודלים המקוריים
=================================================

זו גרסת ניסוי לשורת הפקודה ב־Windows x64. היא קוראת את שמות הקבצים
והתגיות ומייצרת תוכנית למיון. היא אינה מעבירה, מעתיקה, מוחקת או משנה
קובצי מוזיקה ותגיות. כל תוכנית מוחזרת עם executable: false.

אין כאן ממשק גרפי, תמיכה ב־Android או אפשרות Apply. זו אינה גרסת
ההפצה המלאה. קריאת קבצים עשויה לשנות את זמן הגישה שלהם במערכת הקבצים.

מה נדרש
--------
Windows x64 ו־Microsoft Visual C++ Redistributable x64 מעודכן.
הוראות והורדה רשמיות של Microsoft:
https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170

אין צורך להתקין Python, Rust, Git או כלי פיתוח. שני המודלים פועלים
מקומית, בלי הורדת מודלים ובלי שירות AI ברשת. PCRE2, TagLib ו־zlib
מקושרים סטטית; ספריות זמן הריצה של Microsoft הן דרישה נפרדת.

לפני השימוש
-----------
חלצו את כל קובצי ה־ZIP לתיקייה חדשה. אל תעתיקו רק את קובץ ה־EXE.
המודלים המקוריים נמצאים ב־models\original. קובץ SHA256SUMS.txt מפרט
את גיבובי כל קובצי החבילה, מלבד עצמו. provenance.json מפרט את גרסת
המקור, המודלים, ספריות הבנייה והראיות הרלוונטיות.

הדוגמאות שב־examples\source הן קובצי WAV שקטים שנוצרו לצורך הבדיקה.
הן אינן הקלטות מסחריות או חלק מספריית מוזיקה אישית. תיקיית
examples\target ריקה, ותישאר ללא קובצי מוזיקה גם לאחר תצוגת התוכנית.

בדיקה ראשונה ב־PowerShell
------------------------
פתחו PowerShell מתוך תיקיית החבילה. הפקודות הבאות מתאימות גם ל־Windows
PowerShell 5.1 ושולחות JSON בעברית ב־UTF-8 ללא BOM:

$here = (Resolve-Path '.').Path
$exe = Join-Path $here 'singles-sorter.exe'
& $exe --help
& $exe capabilities --json

$OutputEncoding = New-Object System.Text.UTF8Encoding($false)
[Console]::InputEncoding = $OutputEncoding
[Console]::OutputEncoding = $OutputEncoding
$request = @{
    schema_version = 2
    mode = 'Sort'
    source = (Resolve-Path (Join-Path $here 'examples\source')).Path
    target = (Resolve-Path (Join-Path $here 'examples\target')).Path
    settings = @{}
    ai_profile = @{
        Configured = @{
            bundle_id = 'original-v14-ner-3.7.5'
            model_directory = (Resolve-Path (Join-Path $here 'models\original')).Path
        }
    }
    personal_aliases = $null
}
$request | ConvertTo-Json -Depth 10 -Compress | & $exe plan-files --json

התוצאה מופיעה ב־JSON. חפשו status: "ok", תוכנית תחת result.plan,
ושמות האמנים שזוהו. executable נשאר false. בדוגמת הזיהוי המקורית
ישראל כהן אמור להופיע כאמן. אין צורך להפעיל פקודה נוספת כדי לבצע מיון:
הפעלת מיון ממשי אינה נתמכת בגרסה הזאת.

לבדיקה בלי AI, החליפו רק את הפרופיל ושלחו שוב:

$request.ai_profile = 'Disabled'
$request | ConvertTo-Json -Depth 10 -Compress | & $exe plan-files --json

המצב Disabled משתמש בכללי המיפוי הרגילים בלבד. התאמה לרשימת האמנים
יכולה להצליח גם בלי להפעיל אף מודל.

לבדיקה על תיקייה משלכם, שנו את source ואת target לנתיבים מלאים של
תיקיות קיימות. התיקיות חייבות להיות שונות. התחילו בעותק קטן ונוח
לבדיקה: זו תצוגה ניסיונית, וכיסוי סוגי התגיות אינו הבטחה לכל ספרייה.
אין דגל model-directory בשורת הפקודה; הנתיב נמסר בשדה JSON כמוצג לעיל.

משמעות דיווחי הזיהוי
-------------------
inference_executed: true מציין שהתחילה לפחות קריאת זיהוי אחת. הוא אינו
מבטיח שקריאת הזיהוי הצליחה או שזוהה אמן. גם קריאה שנעצרה בגלל מגבלת
משאבים עשויה לדווח true. התאמה לשם אמן ללא צורך במודל תדווח false.

המודלים נבדקים מול גיבובים קבועים בכל משימה. מודל חסר, פגום או פרופיל
לא נתמך יגרמו לשגיאה; התוכנה לא תחליף אותם במודל אחר ולא תעבור בשקט
ל־Disabled. שמות האמנים נשמרים בסדר הזיהוי, לרבות כפילויות לפי כללי
הגרסה המקורית. תווית הפרופיל כוללת את גרסת סביבת spaCy המקורית;
מטא־נתוני מודל singer_ner_he עצמו הם גרסה 2.0.0.

מגבלות ובטיחות
--------------
לזיהוי יש מגבלות קלט ועבודה. חריגה אינה מקצרת את הקלט ואינה מחזירה
תוכנית חלקית. הודעות PLANNING_RESOURCE_LIMIT, PLANNING_CANCELLED או
PLANNING_ALLOCATION מציינות שהמשימה נעצרה בלי תוכנית להמשך ביצוע.
לא ניתן להבטיח התאוששות ממחסור כולל בזיכרון של מערכת ההפעלה.

בספריית הזיהוי קיים ביטול שיתופי; לכלי CLI הזה אין מטפל Ctrl-C שיתופי.
Ctrl-C או סגירת החלון יכולים לסיים את התהליך, ואין בכך הבטחה לקבלת
הודעת ביטול מסודרת. בכל מקרה אין אפשרות לבצע שינוי פיזי בקבצים.

פקודות classify ו־plan הישנות עובדות על עובדות שסופקו ב־JSON ואינן
מפעילות מודלים. לכן native_inference ברמת היכולות הישנה נשאר false.
יכולת הזיהוי של תצוגת הקבצים מופיעה תחת:
result.capabilities.real_file_planning.native_inference

בדיקת החבילה המובנית
-------------------
smoke.ps1 הוא כלי בדיקה ל־Windows PowerShell 5.1 ומעלה. הוא מעתיק את
החבילה לתיקיית בדיקה זמנית עם שם בעברית, מפעיל את הדוגמאות ללא Python
וללא תיקיות כלי פיתוח ב־PATH, ובודק גיבובים, תוכניות ושגיאות צפויות.
הוא בודק גם שתוכן הקבצים, שמותיהם, ההרשאות וזמני השינוי נשארו ללא שינוי.
הדוח חייב להיכתב מחוץ לתיקיית החבילה. למשל:

.\smoke.ps1 -PackageRoot $here -ReportPath (Join-Path $env:TEMP 'original-ai-preview-report.json')

אם Windows חוסם הפעלת סקריפט שהורד, אל תשנו מדיניות אבטחה רק לצורך
הבדיקה. אפשר להשתמש בדוגמאות הידניות לעיל ולבדוק עם מנהל המחשב.
