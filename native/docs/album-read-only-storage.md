# Read-only Album target and journal ownership

This native-only continuation sits on the source-reviewed cross-volume Album boundary and original-location inspector. It introduces no descriptor activation, host command or mutation operation. `WindowsAlbumReadInspection` cannot convert into `WindowsMutationStorage`, a source root, a cleanup session or a writable grant. Its caller must already have a validated recorded descriptor and a freshly selected original containing parent, target root and journal root. The original-parent inspector remains opaque and can probe only the recorded exact native leaf.

Opening this absent-source owner requires a fresh `Absent` result; original or foreign presence is refused. Later original-leaf probes preserve the existing three-way result and errors. The executor must re-probe that leaf before using source absence for each validated recorded source reference and at the final boundary. It must never turn a present foreign object into source authority. Ordinary existing-source reopening uses its separate fresh source grant. Missing legacy native alias evidence remains unresolved.

Journal names, full identities and observed lengths are retained at construction. The reader takes only a retained index, never a caller path. Each journal is a single safe `.jsonl` leaf, checked for exact native name/reference, full identity, regular-file kind and length before reading. Read chunks are at most 64 KiB, followed by a bounded EOF probe, final identity/length/representation checks and held-root ancestry revalidation. Cancellation and actual-byte callbacks include the EOF boundary; failed reads yield no partial successful journal. There are at most eight retained journals, each at most 64 MiB. Strict parser record/operation ceilings remain separate and unchanged.

Target lookups also take only retained indices. Every ledger reference must be a strict descendant of the recorded target root, have a safe relative path, expected kind and full recorded parent identity. Every traversed parent must occur in the directory ledger with a full identity. The read owner pins all traversed no-reparse parents and checks their identities and native references before and after content. Created-directory pins can remain held through all file observations and must be revalidated before report projection. Root ancestry is likewise retained and revalidated. The ledger admits at most 12,288 entries (the existing 4,096-operation plus 8,192-directory ceilings) and depth 128; it does not authorize arbitrary target traversal.

Metadata observation, main-stream hashing and exact full-stream hashing are separate methods. Their sequencing is the strict executor replay's responsibility: all required destination metadata and the copied cohort prepass must complete before any content read. The shared copied-Move stream implementation is extracted without changing its existing source/target-role checks, exact stream inventory/identity/representation verification or EOF accounting. Full-stream reads require a recorded target identity. Historical whole-object journals retain their existing main-stream-only digest baseline; this owner cannot create missing historical ADS evidence. Media reads stream with bounded memory and no aggregate-content byte cap. Observations cover an inspection interval, not an atomic library snapshot after file leases close.

Eighteen authored Windows tests cover the absent-source owner, distinct reappearance, exact journal and target admission, stale roots and overlap, full owned-tree snapshots (identity, kind, attributes, owner/group/DACL/access-control SACL, creation/write time, main and fixture ADS hashes), real chunk/EOF cancellation, fresh complete reinspection, retained directory checks, parent/root relocation, native sharing refusal, growth/EOF, probe errors and reparses. Access time is excluded because reads may update it. Tests never silently skip missing capabilities. Read-only journal bytes in these primitive fixtures are deliberately not valid Album replay records: strict descriptor/replay acceptance belongs to the next slice. The exact-count native CI gate is authored; Rust compilation, formatting and actual Windows execution remain pending.

## Journal replay to target-ledger handoff

`WindowsAlbumJournalInspection` is a separate unbound type. It exposes only the fixed journal set and original-leaf probe; it has no target lookup methods. Its once-only journal read retains immutable bytes for the executor's strict replay. The consuming `bind_targets_observed` rereads every retained journal through the existing full identity/name/length/chunk/EOF checks and requires byte-for-byte equality with the replayed bytes. It revalidates the same held target/journal roots and checks the exact original leaf remains absent before and after ledger admission. The returned `WindowsAlbumReadInspection` has no rebinding method, including for a valid empty ledger. Cancellation/error releases the consumed owner without a bound inspector.

The executor must supply only its separately validated strict-replay target ledger; discovery-history IDs are never adopted as current target evidence. The two-stage type does not parse phase records, claim their authenticity or grant mutation authority. It rereads actual bytes rather than trusting a cached hash after reopening. Journal content may change later; the final higher-level report must preserve its inspection-interval wording and apply its final journal/original-leaf/directory evidence checks. At most eight 64 MiB journal byte buffers are retained in this native primitive, with one additional journal-sized reread buffer during binding. This explicit bounded journal-memory cost is separate from streaming media verification and remains a reason for the later indexed/streamed journal parser.

Six additional native cases (24 total in the read-owner gate) exercise exact byte rereads, unread/repeated state refusal, a once-bound empty ledger, same-ID/same-length content replacement, original-root reappearance during binding, actual reread-chunk cancellation and fresh reinspection, and binding every member of a multi-journal set. These remain authored source evidence until native CI runs.
