# Retained-effects recovery review (inactive draft)

The read-only inspector binds its result to all three original journal hashes and keeps original operation/event history separate from current observations. It resolves recorded source, stage, publication and directory references only under the original, currently granted fixed local provider roots. It never treats a missing/unavailable reference as evidence that an earlier effect did not occur. Current content hashes describe the bytes read now, not attribution of an unacknowledged earlier mutation.

Bounds are 4,000 distinct references, 64 MiB per file, 256 MiB content per review (plus at most one byte to detect overflow) and 2 MiB rendered result. Cancellation and caller-held diagnostic exclusion apply. No journal, source, stage, destination or permission is changed. The inspector is not wired into the app yet.

Intended parent/name candidates are looked up through bounded complete listings, with a 20,000-entry aggregate limit; a same-name current object is only a candidate, never attributed to the historical call. Before acknowledgment can be enabled, the UI must explicitly show remaining unknown effects and verify unchanged original hashes at acceptance. Acknowledgment must be a new separately checked private receipt, never an edit to old history. Its plain-language meaning is keeping the current effects and allowing a new preview; it cannot assert that the old attempt succeeded, replay it or silently remove staging files. Admission must revalidate receipt binding and current root grants, and renderer input cannot manufacture authority.
