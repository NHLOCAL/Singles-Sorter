# Fresh read-only Album original-location primitive

This native-only slice implements the approved original-parent boundary from `docs/superpowers/specs/2026-10-12-album-restart-inspection-design.md`. It does not activate Album restart or consume the active copied-album header changes.

The host must create `WindowsAlbumInspectionParentGrant` from a fresh native directory choice and full observed Windows identity. Its separate validation permits a local drive anchor without weakening `WindowsSelectedRootGrant` or creating a mutation root. `WindowsAlbumOriginalLocationInspection::open_observed` consumes that grant and a recorded native original-root `MutationObservation`. It checks the selected parent identity, local NTFS backing, held no-reparse ancestry and the exact native parent-reference/UTF-16-leaf relation. The saved selected spelling and display name are not lookup authority.

The inspector has only `inspect_original_observed`. It exposes no parent handle, arbitrary child lookup, sibling enumeration, generic root, writable storage or cleanup operation, and implements neither serialization nor cloning. Its handles request existing-object/read-only access through the established native read helpers. Every acquisition and probe uses the caller's actual cancellation flag and `WindowsInspectionEvent::Probe` callback. Cancellation and probe failures are returned before interpreting absence. An existing original directory, a foreign object and native not-found are distinct outcomes; reparse objects are refused. A present object never becomes a source subtree grant.

The caller remains responsible for strict recorded-descriptor validation, media/target/journal grants, expected-presence semantics and re-probing the original leaf while inspecting descendants. This primitive alone makes no statement that an Album job completed. It cannot invent a missing original native name for a historical short-alias record. The current whole-object historical ADS limitation and all recorded-input ceilings remain in the design.

Thirteen authored Windows tests cover full owned-tree/main/known-ADS no-write snapshots, original disappearance and same/foreign reappearance, a file replacing the directory, wrong/replaced/moved parents, alias/reference mismatch, malformed leaves, cancellation/probe refusal, parent relocation before and at the final observation boundary, reparse parent/leaf and a drive-anchor grant. Final same-held-parent identity/native-path validation is required after the leaf probe for both absent and present results. A directory handle is not treated as a universal namespace-exclusion guarantee: the relocation fixture requires either an exact native sharing refusal or stale/error after successful relocation. Cancellation at that final boundary stays cancelled. The drive-anchor case creates nothing in the drive root and probes one unique absent test leaf; it is a native grant test, not completed-job evidence. Junction setup is an explicit owned fixture action outside inspection. The CI exact-count native gate is added; no case silently skips an unavailable capability.

Only source/diff checks are available locally. Rust compilation, formatter output and all thirteen native test executions remain pending Windows CI. The later cross-volume Album restart acceptance must retain its owned second-volume target through restart, either in the top-level fixture lifetime or by reopening while its owner is still alive.
