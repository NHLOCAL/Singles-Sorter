# Explicit retained-effects acknowledgment (inactive seam)

`RetainedEffectsAcceptance` is not called by the app or admission policy yet. Its caller must hold diagnostic exclusion and obtain explicit informed consent in the native review UI. Acknowledgment means keeping the current effects, including plainly identified uncertainty, and permitting a new preview. It never credits an old operation, rewrites history, retries a provider action, removes a stage or alters grants.

The seam repeats the entire read-only review and refuses if its digest differs from the displayed review. Both original fixed-provider roots must still have current read grants and fresh directory observations. The new receipt binds execution/job/plan IDs, exact authority/state/index hashes, both roots, the full review and its digest, plus explicit retained-effects and uncertainty consent. Only that exact binding can later be considered by admission; new execution must still pass the original plan, current grants and all provider checks.

Each acceptance attempt creates a new app-private UUID receipt using exclusive/no-follow creation, explicit descriptor ownership, sync and exact readback. Existing receipts are never replaced. A crash-partial JSON receipt remains as evidence and does not authorize admission; a later explicit retry can create another immutable receipt. The reader validates bounded regular files and exact original/root/review bindings. No global power-loss durability or provider identity/CAS guarantee is claimed.

Bounds: 3 MiB per receipt, 1,000 receipt files and 64 MiB private receipt storage. Admission callers must supply a bounded aggregate read budget. Unknown journal authority remains blocked. Missing old Move URIs remain explicit current observations and never establish that an unacknowledged historical effect did not happen. UI wiring, reader/admission integration, receipt export and actual acceptance/restart tests require separate review before activation.
