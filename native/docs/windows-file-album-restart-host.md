# File-Album restart inspection in the desktop host

This source candidate composes the strict data-only file-Album descriptor and
read-only native owner with the desktop recovery screen. Native compilation,
Windows host fixtures, and staged/extracted consumer acceptance are required;
the portable UI/helper checks are not runtime proof.

## Fresh selection and retained evidence

The history list displays `.album.jsonl` file-Album jobs, including records with
missing physical journals. Those records never claim that current files are
complete. Whole-object `.album-move.jsonl` jobs remain visible with separate
unsupported guidance until their own read-only reopening path is integrated.
Orphan, malformed, and unsupported records remain visible.

For a present original source, the user selects that directory and the target
again. A schema-2 copied-Album record can also display its recorded original
parent. The user must explicitly choose that the source no longer exists and
select the original parent. Neither historical completion nor a failed path
lookup switches modes automatically. Schema-1 Copy records do not acquire this
missing-source capability. All selections use a separate recovery-token registry,
are bound to the retained record, and are revoked by refresh/close.

The first discovery retains exact journal identity, length, modified evidence and
SHA-256. Before native inspection the host rechecks those observations. The
native read owner independently compares each first held read's SHA-256, then
revalidates the exact bytes again when consuming its fixed lookup ledger.
Recorded paths, source absence and parsed descriptors remain data; none creates a
mutation scope, replay command, cleanup command or generic path lookup.

## Current report

Physical file evidence keeps each unique physical index even when several files
share one original Album operation. Missing physical evidence stays unverified.
The ordinary result requires every file to be currently committed, all requested
file and directory metadata to be verified, strict terminal records, the exact
completed Album IDs, no pending directory/cleanup/metadata phases, and all current
root/directory evidence to agree. A missing source directory is expected only
when its exact original reference and full identity have a validated cleanup
acknowledgment. Reappeared or foreign objects remain unresolved/refused.

The renderer independently rejects truncated/duplicate physical rows, absent
required root/terminal evidence, contradictory source location, and changed
metadata in a purported all-clear response. Directory/terminal details are
optional, paginated display, while any unresolved condition remains visible in
the concise result. Paths are read-only, bidi/control escaped display values.

Inspection uses measured cancellable reads. A stopped pass has no completed
report; the retained resume token only prioritizes the next read and every file
is reverified. The existing fixed journal/descriptor/ledger bounds still apply;
this is not a claim of unbounded library-size support. No media-size total cap is
substituted for chunked hashing.

## Mandatory evidence

- The actual host test performs real Album Copy and actual cross-volume root
  Album Move, drops the first Host, makes fresh recovery selections, and checks
  every physical file plus scope evidence. It injects missing terminal, metadata,
  cleanup, file and mapping evidence into a live result to require a warning.
- Cancellation fires from an observed media-byte callback through the actual Host
  ownership path, checks no report/Busy release, and resumes with fresh reads.
  Full owned namespace, identities, attributes, times, main hashes and bounded
  authored named-stream bytes stay unchanged during inspection.
- Wrong parents, foreign recreated source roots, changed named streams and a
  same-length/same-time rewritten journal cannot become an all-clear.
- Both staged and extracted packaged EXEs must pass real process restart for
  file-Album Copy, cross-volume root Move with explicit parent selection, and
  cross-volume mixed Move with a present source. The two-volume cases execute
  inside the lifetime of their owned target directories. The consumer records
  actual displayed file counts, root/directory evidence and measured progress.
- The package gate requires all file-Album restart checks bound to the same EXE
  and complete package manifest as the other physical execution evidence.
