## Candidate effect integration, isolated owned QA only

Shared JNI staging is already present in public base `3bac1e7`; this delta does
not replace native writers or alter the license/ABI/model graph. The retained
five-field repairs go to `OriginalPlanning.stageRepair` in a fresh private UUID
cache. Input/output are separate create-new/no-follow regular files. Java rereads
actual staged bytes using the returned staged length and SHA before provider
writes. Unsupported native repair is recorded explicitly; original metadata-read
failure never becomes a tag save. Rename and metadata outcomes remain independent.

The process-owned one-attempt worker retains lifetime/cancellation ownership.
Fix has an explicit source-only root contract; Sort keeps both roots and its old
receipt policy. Fix gets a separately named receipt policy and explicit mode.
Before provider effects: bound authority/event/estimated journal bytes and total
original bytes, revalidate source grants/observations/content, and inspect retained
namespace reservations. The estimator stays below the existing 8 MiB journal and
10,000 event ceilings; a refusal does not truncate an original plan.

Changed tags use an owned empty stage directory/file, then move the untouched
original into a fresh `.singles-original-UUID` directory. Original bytes and the
pre-rename URI are acknowledged before renaming the backup to `original.backup`.
The exact final backup name, reference and original hash must be verified before
publishing the independently verified staged bytes to the exact intended name.
Every provider return is recorded. Adjusted name/type/scope produces a retained
`effect-mismatch`, never a false checked observation. No error/cancel path deletes
backups or staged content. Only the owned, freshly observed empty stage directory
can be deleted; final acknowledgment follows that checked cleanup and late hashes.

All retained journals, including completed ones, reserve owned original/staging
namespaces independently of recovery acceptance. Missing/lost-return objects
reserve their recorded containing parent. Files reserve their containing directory
to avoid treating pathname spelling as a file-identity proof. Existing owned
directories use fresh fixed-provider ancestry; unknown ancestry refuses admission.
No lowercase transform establishes disjointness. Temporary namespace release needs
an exact checked cleanup or completed Copy relocation certificate AND a fresh
complete parent listing that proves the old child absent. A null query,
FileNotFound, partial listing, current same-name child or unknown response alone
never releases a scope. Backup directories never have release certificates.

Current UI repair flags and optional observed filename are preserved. Backup-only
progress removes the current-source filename claim while retaining the historical
renamed flag and observed original-byte counter. A clean acknowledged unsupported
or original-read failure continues later files with partial status. Failures,
cancellation and unresolved effects stop dependent operations. Readiness reports
fixed allowlisted phase/code diagnostics, and terminal evidence retains original
field/native errors. No shared UI source was rewritten.
